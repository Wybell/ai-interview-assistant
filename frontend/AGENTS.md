# AI 面试助手前端协作指南

本文件适用于 `frontend/` 下的所有文件。必须与仓库根目录的 `../AGENTS.md` 一起阅读：根目录文件负责全项目和后端约束，本文件负责前端产品、体验、接口联调和交付规则。

## 产品目标

构建一个精致、简约、对用户友好的 Vue 3 AI 面试训练应用。它是面向真实学习工作的训练工具，不是营销网站，也不是由互不关联的卡片拼出的演示页面。

核心用户闭环：

```text
选择知识点 -> 生成题目 -> 编写回答 -> 获得评分与反馈 -> 复盘薄弱点
```

用户认证成功后，默认进入面试训练流程。核心训练能力未完成前，不创建落地页、宣传页或装饰性首页。

## 前端自主构建与续建方式

用户已明确授权：前端不采用“带做模式”。用户说“开始”后，Codex 应持续完成整个前端，不在每个小步骤等待确认；只有用户明确要求停止、暂停、改方向或当前工作出现无法安全自行解决的阻塞时才停下。

- 持续完成工程初始化、页面、交互、接口联调、响应式适配、测试、浏览器验证和文档更新，直到前端达到可交付状态。
- 每完成一个实质阶段，仍要在评论消息中简短说明进展，并立即更新本文件的“当前状态与最高优先级”。
- 用户可以随时中断任务。收到停止或暂停指令后，立即停止新的修改和长时间命令，不撤销已经验证的工作。
- 用户之后说“继续”时，先阅读本文件、检查 `git status`、最近提交、`package.json`、当前源码和本地服务状态，再从最后一个已验证阶段继续。不得从头重复或覆盖用户在中断期间的修改。
- 面向用户的说明使用中文。前端代码、配置、接口契约或目录结构变化后，及时更新本文件；影响全仓库时同步更新 `../AGENTS.md`。

```text

  backend/              Spring Boot 后端，在 IntelliJ IDEA 中打开
```

- 新产品界面不得继续修改 `backend/src/main/resources/static`；其中页面仅用于历史兼容。
- 不将后端源码、配置、凭证或数据库逻辑复制到前端。

## 技术方向

未获得用户确认前，使用以下技术栈：

- Vue 3、Vite、TypeScript
- Vue Router：路由和路由守卫
- Pinia：认证用户、模型偏好和面试会话状态
- Axios：普通 JSON 接口
- Element Plus：表单、弹窗、表格、下拉框等可访问性基础组件
- `@lucide/vue`：常见界面图标
- ECharts：仅在后端提供真实、可图表化数据时使用

按职责组织代码，`App.vue` 只负责组合，不成为超大页面组件：

```text
src/
  api/          HTTP 客户端和接口模块
  components/   可复用布局、通用组件和业务组件
  router/       路由与导航守卫
  stores/       Pinia 状态
  styles/       设计令牌、全局样式和共享组件样式
  types/        API 类型和视图模型类型
  utils/        格式化与流式解析工具
  views/        路由级页面
```

## 前端编码规范

以下规则已从项目提供的《前端开发规范文档》提炼并结合 Vue 3 项目结构落地。目标是让代码简洁、一致、可读、具备防御性，并在不牺牲可维护性的前提下保持性能意识。

### 命名

- Vue 单文件组件、页面和布局文件使用 `PascalCase.vue`，例如 `LoginView.vue`、`QuestionPanel.vue`、`AppLayout.vue`。这是对通用文件命名规则的 Vue 项目例外，便于组件导入、识别和现有架构保持一致。
- 普通 TypeScript、样式、工具和接口模块使用全小写连字符命名，例如 `auth-api.ts`、`score-stream.ts`、`app-layout.css`。禁止使用中文、空格或无语义的文件名。
- 变量、函数、组合式函数、状态字段使用语义化小驼峰命名，例如 `selectedModel`、`isSubmitting`、`getAvailableModels()`、`handleScoreSubmit()`。避免 `a`、`data`、`list` 这类无上下文名称。
- 常量使用全大写加下划线，例如 `MAX_ANSWER_LENGTH`、`REQUEST_TIMEOUT_MS`。不把可变运行状态伪装成常量。
- CSS 类名使用全小写连字符命名并体现模块职责，例如 `.practice-workspace`、`.score-result`。ID 仅在确有唯一锚点需求时使用，并遵循同样规则。
- 对外暴露的 Vue 事件使用 `kebab-case`，例如 `update:model-value`、`score-complete`；事件处理函数使用 `handleXxx` 命名。

### TypeScript 与 Vue

- 使用 TypeScript、ES6+、`const` 和必要时的 `let`；禁止 `var`。项目启用格式化工具后，由格式化工具统一单引号、分号、缩进和换行风格。
- 不保留未使用的变量、函数、导入或失效注释。能用明确类型表达的规则，不用模糊的 `any` 绕过。
- Vue 组件固定按 `<template>`、`<script setup lang="ts">`、`<style>` 顺序组织。组件只承担一个清晰职责，页面负责组合，通用交互拆为可复用组件或组合式函数。
- Props 必须使用 TypeScript 类型定义；可选 Props 必须有明确默认值或可空语义。`emit` 事件同样定义参数类型。
- 复杂业务流程、流式解析、安全边界和非直观的兼容逻辑必须在代码块前用简短中文注释说明“为什么”。不要给显而易见的赋值或模板标签写叙述性注释。
- 外部输入都不可信，包括路由参数、表单、接口响应和 AI 文本。前端进行必要的长度、必填和类型校验，但不替代后端校验。
- 不使用 `v-html` 直接渲染 AI 或接口文本。除非专门引入并验证净化策略，否则一律按纯文本渲染。

### CSS 与组件样式

- 样式属性按“布局与定位 -> 盒模型 -> 排版 -> 视觉效果 -> 动效”排序，保持同一组件内一致。
- 禁止常规行内样式；特殊的运行时尺寸或 CSS 变量场景必须有明确理由。避免使用 `!important`，优先调整组件边界、选择器和设计令牌。
- 颜色、间距、圆角、阴影、层级和动效时长优先使用设计令牌。不得在多个组件中散落近似但不同的硬编码值。
- 组件样式默认局部化；全局样式仅放入重置、字体、设计令牌和确实跨页面的基础规则。
- 图片在引入前检查尺寸和体积；使用恰当格式、响应式尺寸和懒加载。不得把超大图片直接作为普通界面资源。

### 请求、状态与日常质量

- 所有异步请求都必须覆盖 `loading`、`error` 和空数据状态，且避免重复提交。不能只实现成功态。
- 复用 API 客户端、错误处理、格式化和流解析逻辑，遵循 DRY；同时避免为了形式拆出没有独立职责的抽象。
- 正式提交前移除敏感或无意义的 `console.log` 调试输出。必要的开发日志不得输出密码、JWT、API Key、用户回答全文或 AI 原始敏感错误。
- 提交前执行格式化、类型检查、相关测试和 Vite 生产构建；发现界面变化时还要完成桌面与移动端视觉检查。

## 接口契约与安全

OpenAPI 是前端接口的正式契约。实现或调整任何联调前，先查看正在运行的后端文档：

- Swagger UI：`http://localhost:8082/swagger-ui.html`
- OpenAPI JSON：`http://localhost:8082/v3/api-docs`

普通接口统一使用如下响应结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

- 业务数据只从 `response.data.data` 读取，不围绕旧版原始字符串响应编写 UI 逻辑。
- 失败时展示服务端返回的非敏感 `message`。遇到 `401` 时视为登录失效：清除本地 Token 并跳转 `/login`。
- 认证、授权、参数校验、模型可用性和业务异常仍属于后端职责；前端必须清晰展示结果，不得绕过。
- 前端仅保存当前浏览器会话所需的短期 JWT。密码、JWT Secret、数据库配置、AI API Key、Provider 端点和真实密钥不得出现在前端源码、已提交的 `.env`、日志、截图或文档示例中。
- 受保护的普通请求使用 `Authorization: Bearer <token>`。不得提交原始 Provider 名称、模型代码、端点、凭证或用户 ID 作为覆盖参数。

### 当前可用接口

| 用户能力           | 正式接口                                          | 前端规则                                                                        |
| ------------------ | ------------------------------------------------- | ------------------------------------------------------------------------------- |
| 注册与登录         | `POST /api/auth/register`、`POST /api/auth/login` | 使用 Swagger 规定的表单请求体；仅在成功后保存 `data.token` 和 `data.username`。 |
| 查看可选模型       | `GET /api/ai/models`                              | 仅渲染服务端返回的模型，不在前端硬编码 Provider 列表。                          |
| 读取或更新当前模型 | `GET` / `PUT /api/users/me/ai-preference`         | 只提交 `{ "modelId": number }`；成功响应后才更新界面选中态。                    |
| 生成题目           | `POST /api/question/ask`                          | 使用 JSON `{ "tag", "refresh" }`；新界面不得调用已废弃的 GET 接口。             |
| 评分回答           | `POST /api/question/score`                        | 使用 JSON `{ "tag", "question", "answer" }`；不得用本地猜测结果冒充服务端评分。 |
| 查看错题           | `GET /api/mistakes`                               | 直接渲染服务端列表；错题判定规则由后端负责。                                    |
| 查看学习进度       | `GET /api/progress`                               | 仅渲染每个知识点的 `totalCount` 与 `avgScore`；不得虚构每日、总计或趋势统计。   |

### 流式评分边界

- 当前 `GET /api/question/score/stream` 是已废弃的历史兼容接口。新界面绝不在 URL 中携带 JWT，也不使用历史 `token` 查询参数。
- 浏览器原生 `EventSource` 不能附加 `Authorization` 请求头，因此不得通过 Query Token 规避这个限制。
- 最终流式评分必须使用正式的 Bearer 认证契约，并把流解析隔离在一个工具模块中。若当前接口临时保留，可使用携带 Authorization 请求头的 `fetch` 解析 `text/event-stream`；正式发布前应提升为非废弃接口契约。
- 界面必须区分普通文本增量、包含 `AiScoreResult` 的 `event: done` 和失败的 `event: error`，并提供明确的加载、失败、重试和取消/断开状态。

## 界面与体验质量基线

每个界面必须精致、简约、对用户友好。这是不可妥协的产品要求。

- 为重复学习操作设计：安静、专注、便于扫读且高效。优先使用克制的侧边栏、简洁顶栏和清晰的主工作区。
- 第一个认证后页面必须是真实的面试训练体验。训练闭环未可用前，不构建装饰性落地页、巨型 Hero 或产品预告页。
- 重大页面编码前先形成经确认的视觉规格。视觉概念工具可用时，为完整页面及关键状态生成清晰概念图；后续实现遵循确认后的设计，不能边写边随意发挥。
- 实现前先建立小型设计系统：颜色令牌、字体、间距、边框、圆角、图标、阴影、动效和组件变体。必须复用，不复制粘贴一套套临时 CSS。
- 使用纯白或明确指定的背景、深色中性色文字、克制的青绿/绿色主操作色，以及清晰的成功/警告/错误语义色。不得把产品做成单一色相、深蓝灰、米色、棕色或紫色渐变界面。
- 页面区域应开放且有明确目的。不得卡片套卡片、给每个区域加悬浮大圆角容器，或用装饰性 Bento 卡片网格代替真实布局。
- 除非确认的视觉规格另有要求，控件和真实工具表面使用 6px 到 8px 圆角。文字变化不得导致工具栏、按钮、磁贴或输入框尺寸跳动。
- 有熟悉图标时使用 Lucide 图标。纯图标工具按钮必须提供悬浮提示；文字按钮只用于提交、保存、重试、退出等明确命令。
- 不添加视觉填充物：渐变光球、散景、无意义标签、虚假系统指标、虚假动态或应用内功能说明文字。
- 仅在真正的落地页 Hero 中使用大展示字体；训练工作台和仪表工具中使用紧凑、易读的标题层级。不得按视口宽度缩放字体，也不使用负字距。
- 使用可读的中文系统字体回退；仅代码样式内容使用等宽字体。按钮、标签和输入框必须明确字体大小、粗细和行高，不依赖浏览器默认值。

### 训练页必须具备的状态

训练页至少区分以下状态：

- 尚未生成题目
- 正在生成题目
- 题目已就绪，用户正在作答
- 回答校验失败
- 同步评分处理中
- 流式评分处理中
- 评分完成，展示分数、建议和参考答案
- 上游/网络/模型不可用失败，并可安全重试
- 登录状态失效

回答编辑器必须显示稳定的字符计数，并遵守服务端 5,000 字符上限。模型切换必须有保存中、成功和失败状态，且只影响之后的 AI 调用。

### 响应式、可访问性与性能

- 必须验证桌面端和移动端。小屏幕可以把侧边栏折叠为抽屉或紧凑导航；训练工作区必须变为连贯的纵向流程，不能重叠、截断控件或溢出文字。
- 每个可交互控件都要有适用的悬浮、焦点、禁用、加载、选中和错误状态，支持键盘操作并提供清晰焦点指示。
- 不能只用颜色表达分数、错误、选中或流式状态。
- 使用稳定尺寸、响应式网格轨道和溢出规则，确保长题目、模型名称和中文文本可读。
- 不直接渲染 AI 返回的非安全 HTML。除非引入明确的净化策略，否则模型输出按纯文本展示。
- 在后端成功响应前，不得宣称请求成功。题目生成、模型保存或评分处理中要防止重复提交。

- 存在视觉概念图时，交付前必须与最终截图对比并修复重要差异。
